## 1. 文档目的

本文档是“归音”从产品验证、原型研发、内部测试到小规模试点的统一基线，供产品、设计、客户端、后端、AI、测试、安全和比赛答辩共同使用。

文档重点回答以下问题：

1. 产品为谁解决什么问题；
2. 首个可用版本必须包含什么、不包含什么；
3. 独立 App 如何通过互联网完成真实语音 AI 交互；
4. 家庭记忆、长期记忆、子女表达风格和 RAG 如何实现；
5. 老人信息如何在授权后形成家庭关怀摘要；
6. 如何控制声线仿真、隐私、诈骗、医疗误导和情感依赖风险；
7. 系统如何部署、测试、监控和逐步商业化。

本文档不是医疗产品注册文件、法律意见书或最终隐私政策。正式公测前，仍需由法律和数据合规人员审查。

## 2. 项目概述

### 2.1 项目愿景

让不在同一座城市生活的家庭，通过自然语音和可信 AI 保持低负担、持续且有温度的联系。

### 2.2 一句话定位

归音是一款面向老人和异地子女的家庭情感协同 App：老人可以通过语音获得陪伴和生活帮助，子女在老人授权的范围内获得可行动的近况摘要，并将真实关怀反馈给老人。

### 2.3 核心原则

1. **AI 不冒充真人**：系统必须明确提示用户正在与 AI 交互。
2. **促进真人联系**：产品优化目标是真实家庭联系，而不是延长 AI 使用时长。
3. **老人拥有隐私决定权**：子女付费不代表默认拥有老人的全部对话。
4. **摘要不等于诊断**：输出生活趋势和待确认事项，不作疾病诊断和用药决策。
5. **数据最小化**：仅收集完成明确功能所需的数据，并允许查看、导出和删除。
6. **高风险场景人工优先**：急症、自伤、诈骗、走失等场景引导联系真人或公共服务。
7. **供应商可替换**：模型、语音识别和语音合成通过统一适配层接入，避免锁定单一厂商。

### 2.4 产品边界

归音提供：

- 日常对话与情感支持；
- 生活知识查询；
- 家庭记忆问答；
- 日程、喝水、活动等非医疗提醒；
- 老人明确需求的记录与转达；
- 经授权的生活状态趋势摘要；
- 子女留言、回拨和关怀任务闭环；
- 高风险信号的提示和升级。

归音不提供：

- 疾病诊断、治疗方案或药物剂量调整；
- 对心理疾病、认知障碍作自动确诊；
- 代替医生、护理员、急救人员或亲属；
- 未经同意的持续监听、定位或摄像；
- 冒充子女进行财务、法律或医疗承诺；
- 未经双方同意采集私人聊天记录或训练声线；
- 将用户原始对话默认用于基础模型训练。

## 3. 用户与需求分析

### 3.1 主要用户角色

#### A. 老人用户

- 年龄通常为 60 岁以上；
- 可能独居、空巢或白天缺少陪伴；
- 可能不擅长打字和复杂操作；
- 普通话、地方口音或方言混用；
- 希望被倾听，但不希望被监控；
- 需要生活帮助、提醒和家庭联系。

#### B. 子女/家庭照护者

- 长期异地工作或居住；
- 希望了解父母近况，但难以高频沟通；
- 担心错过重要需求或异常；
- 希望信息简洁、可信、可以立即行动；
- 需要区分事实、老人原话与 AI 推测。

#### C. 运营与安全人员

- 处理举报、授权争议和账号申诉；
- 查看脱敏后的系统异常和安全事件；
- 管理提示词、知识库、模型版本和风控策略；
- 无权随意查看用户完整对话。

#### D. 后续扩展角色

- 社区工作人员；
- 养老机构照护者；
- 经老人授权的其他亲属；
- 合作医生或健康管理人员。

上述角色不进入首个家庭版 MVP 的主要操作链路。

### 3.2 核心待办任务（Jobs to Be Done）

老人端：

- 当我一个人在家时，我想方便地找人说话；
- 当我不懂手机操作或生活知识时，我想直接开口询问；
- 当我想让孩子知道一件事时，我希望 AI 帮我准确转达；
- 当我不想分享某段谈话时，我希望它保持私密；
- 当我遇到危险时，我希望快速联系家人或紧急服务。

子女端：

- 当我工作繁忙时，我想快速了解父母最近值得关注的事情；
- 当系统发现需求时，我想知道依据、置信度和建议行动；
- 当我看到摘要时，我想一键留言或联系父母；
- 当父母不愿分享时，我希望系统尊重其选择；
- 当系统产生误判时，我希望纠正它并防止重复出现。

### 3.3 典型用户故事

1. 老人按住说话按钮说“今天有点闷”，AI 先共情并询问愿不愿意聊聊，而不是立即判断抑郁。
2. 老人说“我的降压药吃完了”，AI 不推荐药物，而是确认是否需要提醒子女协助购药；老人同意后创建需求。
3. 老人多次提到膝盖不舒服，周报写为“本周三次提到膝部不适，尚未确认持续时间”，并建议子女询问，不输出疾病名称。
4. 子女发送一段真实语音：“妈，我周六下午给你打电话。”老人下次打开 App 时由 AI 提醒并播放原声留言。
5. 老人说“这件事别告诉孩子”，系统将其标记为私密；除明确紧急风险外不进入家庭摘要。
6. 对话涉及验证码、转账或借款时，系统切换为中性声音并提示先联系家人核实。

## 4. 产品形态与信息架构

### 4.1 独立 App 方案

首版开发一个 Flutter App，同一个安装包支持两种角色：

- **关怀模式（老人端）**：大字体、低层级、语音优先；
- **家庭模式（子女端）**：摘要、任务、留言和授权管理。

每个账号可以拥有多个角色，但切换必须清晰，防止老人误进入复杂页面。后续可拆成两个独立安装包。

同时提供一个仅内部使用的 Web 管理后台，用于运营配置和安全审计。

### 4.2 老人端导航

老人端首页只保留四个主要入口：

1. **和归音说话**：默认主按钮；
2. **家人留言**：播放子女真实语音或文字转语音；
3. **今天提醒**：查看和确认提醒；
4. **联系家人**：发起电话或 App 内语音通话。

辅助入口放在右上角：

- AI 身份说明；
- 麦克风状态；
- 隐私与分享记录；
- 设置与帮助。

### 4.3 子女端导航

1. **首页**：最近状态、待关注事项、快速联系；
2. **摘要**：日报/周报和主题趋势；
3. **关怀**：老人需求、提醒、留言及完成状态；
4. **家庭**：成员、家庭记忆和授权管理；
5. **我的**：订阅、安全、设备和数据管理。

### 4.4 管理后台

- 用户与家庭组状态；
- 模型供应商及版本配置；
- 提示词版本；
- 风险词典和规则；
- 告警事件处理；
- 投诉、举报与授权申诉；
- 数据删除任务；
- 系统健康和成本仪表盘；
- 审计日志。

后台默认只展示脱敏信息。查看必要原文需要双人授权、记录原因和完整审计。

## 5. 功能需求

优先级定义：P0 为 MVP 上线必需；P1 为试点期需要；P2 为后续增强。

### 5.1 注册、登录与家庭绑定

| 编号 | 优先级 | 需求 |
|---|---:|---|
| AUTH-01 | P0 | 支持中国大陆手机号验证码登录 |
| AUTH-02 | P0 | 首次登录选择老人或家庭成员角色 |
| AUTH-03 | P0 | 子女生成 10 分钟有效的家庭邀请码/二维码 |
| AUTH-04 | P0 | 老人确认加入家庭组，绑定结果双方可见 |
| AUTH-05 | P0 | 关键授权必须分别确认，不能用一次总授权替代 |
| AUTH-06 | P0 | 支持移除家庭成员、退出家庭组和撤回权限 |
| AUTH-07 | P1 | 支持可信联系人和紧急联系人排序 |
| AUTH-08 | P1 | 支持设备可信校验与异常登录提醒 |

关键授权至少分为：

- 麦克风权限；
- 保存对话文本；
- 保存原始音频；
- 生成长期记忆；
- 向指定家属共享摘要；
- 使用指定人的仿真声线；
- 接收风险提醒；
- 匿名使用数据改进本产品。

### 5.2 实时 AI 语音对话

| 编号 | 优先级 | 需求 |
|---|---:|---|
| CHAT-01 | P0 | 支持按住说话和点击开始/结束两种方式 |
| CHAT-02 | P0 | 通过 WebSocket 建立双向实时音频链路 |
| CHAT-03 | P0 | 流式 ASR，将中间识别结果实时显示为大字字幕 |
| CHAT-04 | P0 | 支持用户打断 AI 播放并立即重新说话 |
| CHAT-05 | P0 | 流式生成文本和流式/分句 TTS 播放 |
| CHAT-06 | P0 | 对话界面持续显示“AI 关怀助手”标识 |
| CHAT-07 | P0 | 网络异常时清楚提示并支持重连 |
| CHAT-08 | P0 | 回复内容经过输入和输出两道安全检查 |
| CHAT-09 | P1 | 支持普通话及试点地区口音优化 |
| CHAT-10 | P1 | 弱网下自动降低音频码率 |
| CHAT-11 | P2 | 方言专用识别和方言语音合成 |

性能目标：

- 开始说话到出现首个字幕：P95 小于 800 ms；
- 结束说话到 AI 开始播放：P95 小于 2.5 s；
- 打断响应：P95 小于 300 ms；
- 会话建立成功率：不低于 99%；
- 首版单次会话最长 30 分钟，接近上限时提示休息。

### 5.3 AI 身份和人格

- AI 名称暂定“归音”；
- AI 使用温暖、耐心、短句式表达；
- 不声明自己是用户的孩子、医生或真人；
- 可以采用经授权的熟悉声线，但表达主体仍是 AI；
- 不制造排他关系，如“只有我理解你”；
- 不贬低或阻碍用户联系真实家人；
- 不主动诱导延长对话；
- 对不确定事实明确说“不确定”并建议核实。

### 5.4 家庭知识库

| 编号 | 优先级 | 需求 |
|---|---:|---|
| KB-01 | P0 | 家庭成员可填写人物、称呼、地点和家庭事件 |
| KB-02 | P0 | 每条资料记录创建人、来源、可见范围和有效状态 |
| KB-03 | P0 | 文本分块、向量化后进入家庭隔离的向量空间 |
| KB-04 | P0 | 回答家庭事实时仅检索当前家庭可访问内容 |
| KB-05 | P0 | 用户可编辑、停用和删除资料 |
| KB-06 | P1 | 支持照片及其文字说明，不做人脸身份推断 |
| KB-07 | P1 | 支持家庭成员共同确认有争议的事实 |
| KB-08 | P2 | 支持家庭时间线和关系图谱 |

RAG 回答规则：

1. 先执行权限过滤，再执行向量检索；
2. 返回文档 ID、来源、相关度和时间；
3. 低于阈值时不将检索内容当成事实；
4. 冲突事实并列呈现或询问用户确认；
5. 家庭资料不得进入其他家庭上下文；
6. 不将检索文本中的指令当成系统指令执行。

### 5.5 长期记忆

记忆分为以下类型：

- `preference`：偏好，如喜欢的称呼；
- `fact`：用户明确陈述的稳定事实；
- `event`：有时间范围的事件；
- `need`：明确需求；
- `relationship`：家庭关系；
- `reminder_context`：提醒上下文；
- `sensitive`：健康、财务或其他敏感信息。

每条记忆必须包含：

- 记忆内容；
- 来源会话/家庭资料；
- 是否为用户原话；
- 置信度；
- 敏感等级；
- 所有者；
- 共享范围；
- 创建时间、最后确认时间和失效时间；
- 状态：候选、已确认、已否定、已删除。

记忆写入流程：

```text
对话结束
  → 模型提取候选记忆
  → 规则检查敏感性和必要性
  → 普通记忆自动暂存 / 敏感记忆请求确认
  → 写入结构化数据库
  → 生成向量索引
  → 用户可查看、纠正或删除
```

禁止仅凭一次模糊表达创建疾病、财务状况、家庭冲突等确定性记忆。

### 5.6 子女表达风格与仿真声线

#### 表达风格

首版不训练“子女人格模型”，只维护结构化风格档案：

- 对老人的称呼；
- 常用问候；
- 句子平均长度；
- 普通话/方言偏好；
- 安慰方式；
- 提醒方式；
- 明确禁用的话术。

风格档案只能影响表述形式，不能改变安全规则、事实或权限。

#### 声线

声线功能默认关闭，P1 再上线。MVP 可使用平台提供的温暖中性声线，并演示授权流程。

声线启用条件：

1. 声音本人完成账号认证；
2. 本人朗读随机授权文本并完成活体校验；
3. 明确选择授权对象、用途和期限；
4. 系统记录授权版本和证据；
5. 老人明确同意听到该声线；
6. 支持随时撤回并触发衍生数据删除；
7. 合成音频带显式 AI 提示及不可感知水印/元数据标识。

以下内容强制使用中性系统声线：

- 转账、借款、账户或验证码；
- 药品剂量和治疗决定；
- 法律承诺和合同；
- 紧急事件处置；
- 系统身份、授权和隐私提示。

### 5.7 提醒和家庭留言

- 子女可创建一次性或重复提醒；
- 老人可通过语音创建提醒；
- 涉及处方药时，仅按用户/医生已设定的内容提醒，不生成新剂量建议；
- 提醒状态包括待触发、已播放、已确认、已跳过、已过期；
- 子女可发送原声留言；
- AI 可以介绍留言来源，但不得改写原声内容；
- 老人可以一键语音回复；
- 所有家庭任务必须有状态闭环。

### 5.8 需求识别与转达

需求状态：

```text
候选 → 老人确认 → 已共享 → 子女已读 → 已接受/拒绝 → 已完成
```

转达前系统应确认：

- 具体要转达什么；
- 发给哪位家庭成员；
- 是否包含敏感信息；
- 老人是否同意立即发送。

涉及明显紧急风险时按照安全策略执行，不以普通需求流程代替紧急处置。

### 5.9 生活状态摘要

摘要分为：

- 即时需求卡片；
- 每日简报（P1）；
- 每周关怀摘要（P0）；
- 月度趋势（P2）。

周报结构：

1. 本周互动概览；
2. 老人主动分享的生活事件；
3. 反复出现的主题；
4. 已获授权的明确需求；
5. 提醒完成情况；
6. 待确认信号；
7. 建议子女进行的关怀行动；
8. 数据范围、缺失情况和免责声明。

报告中的每一条关键结论必须附带：

- 类型：事实、老人原话摘要、趋势或 AI 建议；
- 时间范围；
- 依据事件 ID；
- 置信度；
- 是否经老人授权共享。

报告禁止：

- 输出疾病确诊；
- 使用“健康正常”等无依据结论；
- 对老人进行人格或道德评价；
- 暴露标记为私密的对话；
- 用单次情绪表达推断长期心理状态；
- 隐藏数据不足或系统不确定性。

### 5.10 风险识别与处置

风险分类：

| 风险 | 示例 | 处置原则 |
|---|---|---|
| 急性身体风险 | 胸痛、呼吸困难、摔倒无法起身 | 建议立即联系当地急救；显示一键呼叫和联系人，不自行诊断 |
| 自伤风险 | 明确表达自伤意图或计划 | 保持陪伴、鼓励联系真人、进入高风险流程 |
| 诈骗风险 | 要求验证码、转账、安全账户 | 中断仿真声线，明确警示并建议向家属核实 |
| 走失/认知异常 | 不知道所在地、明显迷失 | 询问可验证信息并按授权联系可信联系人 |
| 医疗咨询 | 询问用药、病症 | 提供一般信息和就医建议，不作诊断和剂量调整 |
| 情感依赖 | 排斥真人、超长连续使用 | 明确 AI 身份、建议休息或联系家人 |
| 家庭冲突/虐待 | 害怕某家庭成员 | 不自动分享给相关成员，提供安全求助选项 |

风险引擎采用“规则 + 专用分类模型 + 大模型复核”的组合，不让单一通用模型独立决定是否通知家属。

上线前需要根据试点地区确定并人工核验急救、报警、社区服务和心理援助联系方式。

## 6. 非功能需求

### 6.1 性能

- REST API 普通请求 P95 小于 500 ms（不含第三方 AI）；
- AI 首包延迟 P95 小于 2.5 s；
- 支持初期 1,000 DAU、100 路并发语音会话；
- 服务可水平扩展；
- 音频上传使用分片和断点续传。

### 6.2 可用性

- MVP 月可用性目标 99.5%；
- 核心服务跨可用区部署作为试点后目标；
- 第三方模型失败时支持有限重试和供应商降级；
- AI 不可用时仍可查看留言、提醒和联系家人；
- 客户端保留最近的非敏感提醒缓存。

### 6.3 适老化

- 正文字号默认不小于 20 sp，并支持更大字号；
- 主要触控区域不小于 48×48 dp；
- 高对比度，不能只靠颜色表达状态；
- 核心流程不超过三层页面；
- 所有重要结果同时支持语音播报和文字显示；
- 支持误触撤销；
- 不使用倒计时制造压力；
- 新手引导可由子女远程协助，但关键授权必须由老人确认。

### 6.4 安全与隐私

- 网络通信全程 TLS；
- 敏感字段使用应用层加密；
- 密钥由云 KMS 管理，不写入代码仓库；
- 对象存储使用私有桶和短时签名 URL；
- 家庭数据按 `family_id` 强制隔离；
- 服务端执行 RBAC + ABAC 权限校验；
- 数据查询默认排除已删除和无授权记录；
- 管理员访问有审批与审计；
- 日志不记录完整令牌、声纹、原始音频或对话正文；
- 定期执行依赖漏洞、越权、提示注入和数据泄露测试。

### 6.5 可观测性

- 指标：延迟、错误率、会话成功率、模型用量和单位成本；
- 链路：客户端—网关—ASR—LLM—TTS 全链路 trace ID；
- 日志：结构化、脱敏、分级保留；
- 告警：AI 供应商失败、成本异常、风险引擎故障、删除任务失败；
- AI 质量：幻觉率、越界回答率、错误记忆率和摘要误报率。

### 7.1 MVP 部署形态

MVP 采用“模块化单体 + 独立 AI Worker”，避免过早微服务化：

- `api-server`：账号、家庭、授权、记忆、报告、任务；

### 7.3 AI 供应商适配层

定义统一接口：

```python
class ASRProvider:
    async def stream_transcribe(self, audio_stream, config): ...

    async def stream_chat(self, messages, tools, config): ...
```

每次调用记录供应商、模型、版本、延迟、Token/音频用量、错误类型和成本，但不在普通监控日志中保存完整敏感内容。

- 中国大陆网络延迟和可用性；

- 是否允许关闭训练用途；
- 内容安全和备案状态；
- 方言/口音识别效果；
- TTS 声线授权与水印能力；
- 并发、价格和服务等级协议。

## 8. 实时语音交互设计

### 8.1 协议

客户端与实时网关使用 WebSocket。音频建议：

- 采样率：16 kHz；
- 单声道；
- 传输编码：PCM16（原型）或 Opus（弱网优化）；
- 分片：20–100 ms；
- 使用 VAD 检测起止点；
- 每个会话有唯一 `session_id`。

### 8.2 WebSocket 消息示例

客户端事件：

```json
{"type":"session.start","conversation_id":"uuid","audio_format":"opus","sample_rate":16000}
{"type":"audio.chunk","sequence":15,"payload":"base64..."}
{"type":"audio.commit"}
{"type":"response.cancel"}
{"type":"session.end"}
```

服务端事件：

```json
{"type":"session.ready","session_id":"uuid"}
{"type":"asr.partial","text":"今天有点"}
{"type":"asr.final","text":"今天有点闷。"}
{"type":"assistant.text.delta","text":"听起来"}
{"type":"assistant.audio.chunk","sequence":1,"payload":"base64..."}
{"type":"safety.notice","level":"medium","message":"建议先联系家人核实"}
{"type":"response.completed","message_id":"uuid"}
```

### 8.3 单轮处理流程

1. 接收音频并实时转写；
2. 输入安全分类；
3. 获取短期会话上下文；
4. 按权限召回长期记忆和家庭知识；
5. 组装系统提示、用户输入、检索证据和工具定义；
6. 模型生成文本或工具调用；
7. 工具结果进行权限和风险检查；
8. 输出安全检查；
9. TTS 合成并返回；
10. 异步提取事件、候选记忆和摘要依据。

### 8.4 上下文预算

- 最近对话：最近 10–20 轮的压缩摘要；
- 用户画像：只取与当前问题相关字段；
- 长期记忆：Top K + 权限过滤；
- 家庭 RAG：Top K + 重排；
- 安全提示：固定、不可被用户内容覆盖；
- 超出预算时优先舍弃低相关度历史，不舍弃安全规则。

## 9. AI 编排与提示词策略

### 9.1 提示词层级

1. 平台安全规则；
2. 产品角色与医疗/财务边界；
3. 当前用户和权限；
4. 当前场景策略；
5. 检索到的家庭事实；
6. 最近会话；
7. 用户当前输入。

家庭知识、网页内容和用户消息都视为不可信数据，不能覆盖高层规则。

### 9.2 工具集合

MVP 允许模型调用的工具：

- `get_current_time`；
- `get_weather`；
- `search_family_knowledge`；
- `list_reminders`；
- `create_reminder_draft`；
- `create_need_draft`；
- `request_share_consent`；
- `play_family_message`；
- `prepare_contact_action`。

所有产生外部影响的工具均使用两阶段提交：模型只能创建草稿，必须由用户确认后执行。

### 9.3 结构化输出

记忆、需求、风险和报告必须使用 JSON Schema 约束生成。例如候选需求：

```json
{
  "title": "协助购买已用完的药品",
  "description": "老人表示家中原有药品已用完，具体药名待确认",
  "source_type": "user_statement",
  "source_message_ids": ["uuid"],
  "confidence": 0.91,
  "sensitivity": "health",
  "requires_confirmation": true,
  "recommended_recipient_ids": ["uuid"]
}
```

### 9.4 防幻觉策略

- 涉及家庭事实时优先回答有来源的内容；
- 无检索证据时明确未知；
- 报告只引用结构化事件，不直接让模型自由总结全部对话；
- 事实抽取与报告撰写使用不同步骤；
- 高风险结论必须规则校验；
- 允许用户对记忆和摘要点“正确/不准确”；
- 将纠正作为新版本记录，不能静默覆盖审计历史。

## 12. 权限模型

### 12.1 数据所有权

- 对话属于参与对话的老人；
- 子女原声留言属于发送者，并授权指定接收者播放；
- 家庭知识归创建者或明确指定的共同所有者；
- 报告是从老人授权数据产生的派生数据，老人可以撤回后续共享；
- 平台仅作为数据处理者保存和处理必要信息。

### 12.2 分享级别

| 级别 | 对话原文 | 主题趋势 | 明确需求 | 紧急风险 |
|---|---:|---:|---:|---:|
| 私密 | 否 | 否 | 否 | 按预先授权和安全策略 |
| 仅匿名统计 | 否 | 是，不含细节 | 否 | 按策略 |
| 家庭摘要 | 否 | 是 | 经逐项确认 | 按策略 |
| 指定内容 | 仅指定片段 | 可选 | 是 | 按策略 |

MVP 默认采用“家庭摘要”，但首次启用必须由老人主动选择，不能预勾选。

### 12.3 服务端强制校验

任何读取敏感资源的请求都必须校验：

```text
身份有效
AND 属于对应家庭
AND 角色允许操作
AND 当前资源可见范围允许
AND 授权未过期或撤回
AND 资源未删除
```

禁止只靠客户端隐藏按钮实现权限控制。

## 13. 隐私、合规与伦理要求

### 13.1 上线前必须准备

- 用户协议；
- 隐私政策；
- 敏感个人信息处理规则；
- 声线采集和使用单独同意书；
- 老人—家属信息共享说明；
- 第三方 SDK 清单；
- 数据保留和删除政策；
- AI 生成内容标识方案；
- 投诉、举报和申诉机制；
- 个人信息保护影响评估；
- 数据泄露应急预案；
- 算法备案、安全评估及生成式 AI 相关合规评估。

### 13.2 数据保留建议

| 数据 | 默认策略 |
|---|---|
| 实时音频缓存 | 会话结束后尽快删除，除非单独同意保存 |
| 原始音频 | 默认不保存；用户主动保存时设置明确期限 |
| 对话正文 | 提供 7/30/90 天或不保存选项 |
| 长期记忆 | 保存至用户删除、撤回或失效 |
| 报告 | 默认 12 个月，可由用户提前删除 |
| 授权证据 | 按法律和争议处理所需期限保存 |
| 安全审计日志 | 根据合规需求设定，不包含非必要正文 |

最终期限应由法律审查和业务必要性共同确定。

### 13.3 删除机制

- 用户可以删除单条对话、记忆、知识资料或整个账号；
- 删除操作进入异步删除队列；
- 同时删除主库、向量库、对象存储、缓存和搜索索引；
- 备份中的数据按照备份生命周期自然过期，并禁止恢复到生产用途；
- 删除任务生成可查询状态和审计记录；
- 撤回声线授权后立即禁止新合成，并启动训练材料和供应商侧数据删除。

### 13.4 AI 标识

- 对话页固定显示“AI 关怀助手”；
- 首次和重新登录时语音说明 AI 身份；
- 仿真声线首次播放和适当间隔再次提示；
- 导出音频包含显式提示和元数据隐式标识；
- 不允许用户关闭法定或必要的身份标识。

## 14. 安全威胁模型

| 威胁 | 主要措施 |
|---|---|
| 家庭间数据越权 | family_id 服务端隔离、对象级授权、自动化越权测试 |
| 账号被盗 | 短期令牌、刷新令牌轮换、设备管理、异常登录提醒 |
| 声线被滥用 | 活体授权、用途限制、不可导出、水印、风险场景切换声线 |
| 提示注入 | 检索内容不可信标记、工具白名单、参数校验、最小权限 |
| 模型诱导转账 | 财务分类器、关键字规则、中性声线、禁止执行金融动作 |
| AI 编造家庭事实 | 带来源 RAG、阈值、结构化证据、用户纠错 |
| 内部人员窥探 | 脱敏后台、按需审批、双人授权、不可篡改审计 |
| 第三方供应商留存数据 | 合同限制、关闭训练、最小化传输、供应商删除接口 |
| 敏感日志泄露 | 日志脱敏、字段白名单、密钥扫描、访问控制 |
| 恶意文件上传 | 类型与大小校验、病毒扫描、私有存储、隔离处理 |

上线前至少进行一次外部或独立人员安全评审。

## 15. 报告生成算法

### 15.1 流程

```text
原始对话
 → 敏感性分类
 → 结构化事件提取
 → 老人分享权限过滤
 → 同类事件聚合与频次计算
 → 异常/趋势规则判断
 → LLM 生成可读文本
 → 事实一致性校验
 → 风险与医疗边界校验
 → 发布给指定家庭成员
```

### 15.2 趋势判断

首版使用可解释规则，避免宣称具有医学预测能力。例如：

- 同一主题在 7 天内出现 3 次，可标记为“反复提及”；
- 与前一周期相比增加，标记为“提及次数增加”；
- 样本少于阈值时写“数据不足”；
- 情绪分类仅作为辅助信号，不直接形成疾病结论；
- 所有阈值可配置并记录版本。

### 15.3 摘要质量控制

- 关键事实必须能追溯到事件；
- 数量由程序计算，不让 LLM 心算；
- 日期和提醒状态由数据库提供；
- LLM 只负责组织语言和提出低风险沟通建议；
- 输出发布前执行 Schema 校验、事实覆盖检查和敏感信息过滤。

- 日常闲聊；

## 21. 成本模型

主要可变成本：

- ASR 音频分钟数；
- LLM 输入/输出 Token；
- TTS 字符数或音频时长；
- 嵌入模型；
- 对象存储和流量；
- 短信验证码；
- 内容安全审核；
- 推送和监控。

单用户月成本模型：

```text
月成本 = 日均对话分钟 × 30 ×（ASR 单价 + TTS 单价）
       + 月 Token 用量 × LLM 单价
       + 存储与流量
       + 短信/推送/安全服务
```

研发时必须记录每次会话的用量，形成以下指标：

- 每有效对话分钟成本；
- 每活跃老人月均 AI 成本；
- 每份周报成本；
- 缓存/RAG 对 Token 的节省比例；
- 不同供应商的质量—延迟—成本曲线。

正式预算需要在供应商选型后按实时价格更新，本文件不固化可能快速变化的单价。

## 23. 创业比赛展示方案

### 23.1 Demo 剧本

1. 老人打开 App，用自然语言与归音交谈；
2. AI 根据家庭知识提到一个真实家庭记忆，同时明确自己是 AI；
3. 老人说生活用品或常用药已用完；
4. AI 复述需求并询问是否转达给女儿；
5. 老人确认后，子女端立即出现需求卡片；
6. 子女点击接受并录制原声留言；
7. 老人端收到并播放留言；
8. 展示周报中的主题趋势、证据、置信度和隐私设置。

### 23.2 答辩核心表达

- 我们不制造“数字子女”，而是连接真实家庭；
- 我们的创新是双向关怀闭环、授权式记忆和可解释摘要；
- 老人拥有信息分享决定权；
- 系统不作医疗诊断；
- 声线有单独同意、水印、撤回和高风险禁用机制；
- 技术原型能够真实联网运行，而不是预录视频；
- 已通过真实老人和家庭的小规模验证。

### 23.3 可形成的研究成果

- 老人语音交互适老性研究；
- 家庭情感协同智能体架构；
- 授权感知的长期记忆与 RAG；
- 老人对话中的可解释需求提取；
- 方言/口音条件下的安全风险识别；
- 以真实家庭联系为目标的 AI 陪伴评测体系。

| production | 正式环境 | 完整安全、审计、备份和合规机制 |

不同环境使用独立数据库、对象存储、密钥和第三方供应商凭证。

## 30. 项目成功定义

项目的成功不定义为“AI 聊得像子女”或“老人使用时间足够长”，而定义为：

1. 老人能独立、安心地使用；
2. 老人理解对面是 AI，并拥有隐私决定权；
3. AI 能在不越过医疗和伦理边界的前提下提供有效帮助；
4. 子女得到的信息准确、克制且可行动；
5. 系统实际促成更多真实家庭联系；
6. 技术、成本、合规与商业模式能够支持持续运营。

归音的最终价值不是复制一个家人，而是让真实家人更及时地出现。
